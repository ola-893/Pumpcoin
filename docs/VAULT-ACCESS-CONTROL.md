# Unora prototype authority and configuration

Custody: manager -> vault fixed-shape managerTrade -> restricted adapter -> configured spot venue -> vault. No manager generic calls, delegatecall, sweeps, investor-share redemption privilege or admin access. Investor allowances govern third-party redemption. All allowances are exact per trade and reset; input/output deltas are checked. Unsolicited adapter dust is left untouched and cannot block the pass-through checks.

`proposeConfig(ConfigArgs)` and apply after one day govern adapter, venue, escrow stream, valuation source, caps/budget, strategy/risk declaration and registry/agentId binding. There is no immediate venue/stream setter. Adapters must bind the correct vault/quote/position pair; venues must have code. Streams must bind the correct vault/quote/chain. Replacing escrow requires zero remaining balances/obligations and no accrued liabilities. Old reserves must be refunded/settled first.

Identity binding requires an existing registration owned by the manager or admin at proposal and application. It identifies a registration, not a proof of software execution. The local registry uses OpenZeppelin ERC721 transfers, but is explicitly a **simulation mock, not a complete deployed ERC8004 registry**. Ownership/controller metadata mutation does not authorize management. A transfer during the notice period invalidates binding application if ownership no longer meets policy.

Configuration hashes commit to chain, vault, tokens, adapter/venue/stream/source, caps, budget, strategy/risk declarations, registration, policy declaration, manager/version, admin and adapter revocation state. Performance periods record effective hashes and manager/identity links. Strategy/risk changes require notice even when an emergency manager key is rotated.

Immediate trusted-admin powers: pause/unpause, revoke adapter, rotate manager with the SAME strategy/risk declaration, transfer admin role, and explicit expense funding/accrual/reversal/settlement/refund inside the lifetime budget. Key/admin changes and revocation record new periods. Price-source admin can update/dispute/restore injected marks; freshness duration is immutable and changing it requires a new governed source. Expense-stream admin can allow/revoke recipients; funding/settlement are still vault-admin-only and an obligation fixes its original recipient/service. These disclosed administrative powers are not permissionless verification of real-world prices, services or liabilities.

There is no proxy or arbitrary sweep. Notice does not guarantee investor exit: positions, pauses, stale pricing or escrow can constrain quote liquidity. Admin can rotate itself to a new key; registration transfer alone cannot do that. Emergency revocation records unavailable NAV honestly when required.

`ServiceExpenseStream` is manual expense escrow, despite the historical class name. Stored obligations bind chain/stream/nonce to service, recipient and amount; settlements/refunds reference this state. Separate phase nonces prevent duplicate requests with changed amounts, and partial amounts cannot exceed remaining funds. Actual ERC20 transfers establish token payment, not service delivery. **Timed FlowPay streaming and an autonomous expense worker are not implemented.**
